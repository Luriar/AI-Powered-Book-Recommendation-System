# 졸업 프로젝트 검증 근거 및 취업자료 활용 기준

## 프로젝트 기본 사실

- 프로젝트명: AI 기반 도서 추천 온라인 서점 (학사 졸업프로젝트)
- 수행 시기: 2025년 1월부터 6월까지
- 학교 및 형태: 북경과학기술대학교 컴퓨터과학기술 전공, 개인 졸업 프로젝트
- 역할: 문제 정의, 설계, 백엔드와 프론트엔드 구현, 외부 도서 정보 처리, AI 연동, 기능 테스트
- 기술: Java, Spring Boot, MySQL, Vue 3, Axios, Python, Flask, DeepSeek API, e5-large-v2, Google Books API
- 근거: 실제 개발 원본 ai-bookstore, 졸업논문, 공개된 API와 UI 소스

## 사용자 문제에서 기능 설계까지

처음 책을 찾는 사용자는 제목이나 저자보다 자신의 감정, 관심 주제 또는 독서 목적을 먼저 떠올리기도 합니다. 이에 따라 문장에 포함된 감정, 상황, 주제를 LLM으로 해석하고 e5-large-v2 임베딩으로 실제 도서 데이터와 의미 유사도를 비교하도록 설계했습니다. 추천된 도서는 단순 채팅 문장이 아니라 웹서비스의 도서 상세와 연결되도록 만들었습니다. 가입 과정에서는 관심 분야를 선택하게 하여 행동 이력이 없는 신규 사용자에게 초기 추천 기준을 제공했습니다.

도서 데이터 수집에는 ISBN과 Google Books API를 사용했고, 설명이 누락된 도서를 대상으로 AI 요약 배치를 구성했습니다. 외부 API 호출 비용과 처리 시간을 고려해 요청 빈도 제어, 병렬 처리, 임베딩 사전 계산과 캐싱을 검토했습니다. 관리자에게는 ISBN 일괄 등록 외에도 수동 등록과 도서 가격 및 재고 수정 화면을 제공했습니다.

## 실제 소스에서 확인한 구현 기능

| 기능 | 직접 확인한 구현 근거 | 이력서 작성 시 표현 |
| --- | --- | --- |
| 도서 관리 | BookController.java, BookService.java, Book.java | 등록, 조회, 검색, 수정, 삭제 API 및 관리자 화면 개발 |
| ISBN 자동 등록 | IsbnBatchRegistrar.java, GoogleBooksService.java | 외부 도서 정보를 ISBN으로 수집하고 등록하는 처리 흐름 구현 |
| 관리자 화면 | BookRegister.vue, BookEdit.vue | 도서 정보와 가격, 재고 수량 관리 화면 구현 |
| 대출 및 반납 | BookService.java, BookDetail.vue | 대출 시 재고 감소, 반납 시 재고 증가 로직 구현 |
| AI 추천 | embedding_query.py, ChatService.java | 자연어 의도 분석과 임베딩 기반 도서 검색 연결 |
| AI 요약 | BookSummaryBatchRunner.java, AiSummaryService.java | 요약 미작성 도서를 선별하여 외부 LLM API 처리 |
| 개인화 초기 설정 | 회원가입 및 관심 분야 데이터 | 신규 사용자 관심분야를 초기 추천에 활용 |
| 사용자 기능 | MyPage.vue, UserController.java | 즐겨찾기, 추천 이력, 대출 도서 및 사용자 관리 화면 |

## 검증된 정량 결과

| 항목 | 논문에서 기록한 개선 전 | 개선 후 | 해석 |
| --- | --- | --- | --- |
| 16권 AI 요약 배치 | 611.7초 | 70.0초 | 약 8.7배 단축, 특정 실험 기록 |
| 추천 전체 응답 | 38.015초 | 16.726초 | 약 2.27배 단축, 특정 실험 기록 |
| 키워드 및 임베딩 관련 구간 | 117ms | 37ms | 약 3.16배 단축, 논문 측정 구간 |

실험 조건과 반복 횟수가 제한되어 있으므로 이 수치를 상용 환경의 성능 보증으로 작성하지 않습니다. 자연어 질문 5개에 대한 주관적 추천 평가는 별도로 기록되었으나 객관적인 추천 정확도 지표나 외부 사용자 테스트 결과는 아닙니다.

## 실제 소스와 과거 설명의 차이

- 도서 삭제는 실제 Java 코드에서 bookRepository.deleteById(id)로 처리합니다. 논문에 설명된 논리 삭제가 구현되었다고 쓰지 않습니다.
- 재고 자동 증감은 도서의 대출 및 반납에 따른 기능입니다. 구매 주문, 결제, 매입, 판매, 회계 또는 실제 ERP 운영 경험으로 확장해 표현하지 않습니다.
- 일부 AI 파이프라인은 CSV 데이터, 외부 API와 모델 환경에 의존합니다. 전체 원본을 독립적으로 실행해 동일 결과를 재현했다고 쓰지 않습니다.
- 본인이 개인 프로젝트에서 수행한 기능과 외부 모델 및 API가 제공한 기능을 구분합니다.

## 직무별 활용 문장 예시

### 온라인 MD 및 ERP 운영 지원

온라인 서점 개인 졸업 프로젝트에서 도서 등록과 검색, 가격 및 재고 수량 관리 기능을 구현했습니다. 관리자가 ISBN으로 도서를 등록하거나 직접 정보를 수정할 수 있도록 화면과 API를 연결했고, 대출과 반납에 따라 재고 수량이 변경되도록 설계했습니다. 실제 판매 주문이나 결제 기능은 구현하지 않았지만, 상품 데이터와 운영 상태를 일관되게 관리해야 하는 문제를 경험했습니다.

### 서비스기획 및 PM/PO 지원

사용자가 도서 제목을 모르더라도 감정과 상황, 독서 목적을 자연어로 설명해 책을 탐색할 수 있도록 서비스 흐름을 설계했습니다. 의도 해석, 실제 보유 도서 검색, 추천 설명 생성을 분리하고 이를 도서 상세, 관심 목록, 대출 기능과 연결했습니다. 성능 개선에서는 추천 응답의 대기 구간과 요약 배치 처리시간을 비교해 개선 방향을 검토했습니다.

### 데이터, AI 및 소프트웨어 엔지니어 지원

Google Books API를 통한 ISBN 기반 데이터 수집, DeepSeek를 통한 요약 생성, e5-large-v2 임베딩 기반 후보 검색과 가중점수 계산을 구현했습니다. 추천 및 요약 파이프라인의 응답과 배치 처리 성능을 논문 환경에서 측정했고, 사용자 웹 화면과 Spring Boot API, Python 서비스, MySQL을 연결했습니다.
